# Portfolio UI Redesign Prompt — Kaveesha Vimukthi

## Project Goal

Redesign the existing portfolio website for **Kaveesha Vimukthi** so the website clearly communicates two connected professional identities:

1. **IT Student / Developer**
2. **Visual Designer / Creative**

The website must feel like **one strong personal brand with two disciplines**, not two unrelated portfolios.

Current portfolio:
https://my-portfolio-gilt-eight-82.vercel.app/

The existing site identifies Kaveesha primarily as an aspiring cybersecurity professional. Keep the technical credibility, but expand the identity so the UI also strongly represents design, visual creativity, UI/UX, branding, posters, and digital creative work.

---

# Core Creative Direction

## Main Concept

### ONE PERSON. TWO DISCIPLINES.

**TECH** → logic, systems, development, problem solving, technology

**DESIGN** → creativity, visual communication, UI, branding, typography, digital art

Primary positioning:

> **IT Student & Visual Designer**

Supporting statement:

> **Building digital solutions through technology and creativity.**

The portfolio should communicate this within the first 5 seconds.

---

Create a **premium modern portfolio** that combines:

# Color System

Use a neutral foundation.

Base:

- near-black / charcoal
- off-white
- muted gray
- soft borders

Use accent colors carefully.

Suggested system:

## Tech Accent

Electric cyan / mint / green

## Design Accent

Warm violet / magenta / coral / creative gradient

Important:

The accents should not become two completely separate color themes.

Both sides should still feel like part of the same brand.

Use color mainly for:

- links
- buttons
- highlights
- selected states
- project metadata
- small UI details

Avoid full-page neon backgrounds.

---

# Typography

Use a modern premium sans-serif.

Suggested style:

### Headings
Large, bold, geometric, editorial.

### Body
Clean, highly readable sans-serif.

### Technical labels
Use a subtle monospace font only for small metadata or technical labels.

Do NOT use monospace typography for the entire website.

Create strong typography hierarchy using:

- very large hero text
- medium section headings
- small uppercase metadata
- generous letter spacing
- controlled line length

---

# Motion Design

Use smooth, purposeful animation.

Required interactions:

- hero text entrance animation
- split-panel hover interaction
- smooth scroll
- project image hover
- subtle button transitions
- section reveal on scroll
- navigation state animation
- cursor interaction where appropriate

Optional:

- subtle magnetic buttons
- image parallax
- project card tilt

Avoid distracting animations.

The goal is:

**premium motion, not animation overload.**

---

# Cursor

Desktop can have a custom cursor interaction.

Normal state:
small clean cursor.

Hovering project/image:
cursor becomes a small labeled circle:

> VIEW

Hovering Tech:
> TECH

Hovering Design:
> DESIGN

Keep it subtle.

Disable custom cursor effects on mobile.

---

# Background

Use subtle visual texture.

Possible background treatment:

- fine grid
- tiny noise texture
- very subtle radial gradients
- oversized abstract typography
- thin lines

The background must remain quiet enough for content to dominate.

---

# Cards

Do not make every element a floating glass card.

Use cards selectively.

Preferred style:

- thin 1px borders
- subtle radius
- dark surfaces
- restrained shadows
- small hover movement

Avoid excessive:

- blur
- transparency
- neon borders
- glowing boxes

---

# Responsive Design

The redesign MUST be fully responsive.

Desktop:
- large editorial layouts
- split hero
- asymmetric design gallery
- generous whitespace

Tablet:
- simplify grids
- maintain visual hierarchy
- preserve dual identity

Mobile:
- stack Tech and Design sections
- preserve clear separation
- keep typography readable
- use simple navigation
- disable heavy hover-only interactions

Mobile should feel intentionally designed, not like a compressed desktop version.

---

# Accessibility

Ensure:

- readable contrast
- keyboard navigation
- visible focus states
- semantic HTML
- accessible buttons
- image alt text
- reduced-motion support

Respect:

`prefers-reduced-motion`

---

# Technical Implementation

Do not rebuild functionality unnecessarily.

First inspect the existing project and preserve:

- existing content
- existing working links
- existing assets
- existing project information
- existing contact functionality

Improve the UI/UX and component architecture without removing useful information.

Use reusable components for:

- Navbar
- Hero
- ProjectCard
- SkillCard
- DesignGallery
- Timeline
- ContactForm
- Footer

Keep the code clean and maintainable.

---

# Important Content Rule

Do not invent:

- certifications
- projects
- companies
- job experience
- awards
- statistics
- client names
- project outcomes

Use existing portfolio information wherever available.

Where content is missing, use clean placeholders that can easily be replaced.
